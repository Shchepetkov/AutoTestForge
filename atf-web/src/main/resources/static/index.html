AutoTestForge

Генератор модульных и интеграционных тестов для Java-проектов на базе ИИ

1. Java-проект

При локальном запуске укажите папку Java-проекта. При запуске через Docker — путь внутри контейнера, например /projects/my-service. Папка должна входить в разрешённые каталоги сервера (ATF_ALLOWED_ROOTS).

Это токен данного сайта. Ключ самой LLM вводится отдельно ниже.

2. Подключение LLM

Qwen — название семейства моделей. Способ подключения зависит от сервера: выберите Ollama или API, совместимый с OpenAI. Адрес и точное имя модели можно узнать у администратора или получить кнопкой «Найти модели».

Адрес должен быть доступен серверу AutoTestForge. В Docker для LLM на вашем компьютере используйте host.docker.internal вместо localhost.

Выберите найденную модель или введите имя вручную. Модель должна быть доступна на указанном сервере.

Для локального Ollama ключ обычно не нужен.

Параметры запроса

Проверка подключения отправляет короткий запрос модели и ждёт до 60 секунд. Ключи используются для запросов из этой вкладки и не сохраняются в хранилище браузера. Выбранные параметры применяются к текущему запуску.

3. Режим генерации

В пробном режиме тесты генерируются без записи в проект и без запуска. Чтобы записать тесты, снимите флажок пробного запуска. Для проверки тестов нужен Docker или установленные Java и Maven/Gradle.

Внешний контекст для LLM (опционально)

Можно добавить несколько MCP-источников (например, отдельные серверы Confluence, Jira, Zephyr) и/или загрузить XML/JSON/TXT экспорт из Zephyr/TMS. Этот контекст попадет в prompt, а LLM должна использовать его для сценариев и добавить в тест JavaDoc-заметку о покрытии и пробелах.

Файлы читаются браузером и отправляются как текстовый контекст; на сервере они не сохраняются как отдельные файлы.
